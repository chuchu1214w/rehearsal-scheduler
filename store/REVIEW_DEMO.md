# App Store 审核演示账号

审核员需要一个能登录、看得到真实感数据、但**看不到真实团员和真实演出**的成员账号。用 `scripts/make_review_demo.py` 生成,全程只调用线上 API,不改动真实演出。

## 运行

在项目目录、用自己的电脑终端运行(需要管理员账号):

```bash
.venv/bin/python scripts/make_review_demo.py            # 默认 https://timetomeet.fly.dev
.venv/bin/python scripts/make_review_demo.py --base http://localhost:8000   # 本机调试
```

脚本会提示输入管理员用户名和密码(只用于本次登录,不保存、不打印,结束时自动退出登录)。成功后只输出三行:

```
审核账号用户名:appreview
审核账号密码:xxxx-xxxx-xxxx-xxxx
演出「审核演示 · 冬季公演」(#N):6 人、3 首曲目,排练 …;排练表 vN 已发布 …
```

把用户名和密码填到 App Store Connect →「App 审核信息」→ 登录信息(见 `ios-listing.md` 第 5 节)。

## 它做了什么

- 演出「审核演示 · 冬季公演」:正规排练从今天开始,约 4.5 周后演出;全员曲只能排在周六,4 场分布在 4 个周六,审核期间总有接下来的排练。
- 名册里 5 位虚构成员(`演示·小林` 等,备注「App Store 审核演示数据」)+ 成员「审核员」,只参加这场演出。
- 3 首曲目,管理员代填并提交全员空闲(工作日晚上 + 周末),求解、填好排练地点后发布。
- 审核账号:没有就开通(用户名默认 `appreview`,可用 `--username` 改);已有就重置密码;被停用就重新启用;审核员自己注销过就重新开通。随后脚本以审核员身份改一次密码,所以审核员登录时不会被要求改密。
- 最后以审核员身份核对:只看得到这一场演出,且排练表已发布。

## 重复运行

可以随便重跑,不会重复建演出、成员或曲目。每次都会生成**新密码**(旧密码作废),所以每次提交审核前跑一次,再把新密码填进 App Store Connect。

- 数据没变且已发布:沿用现有排练表,不重新求解。
- 离演出不足 26 天:整体把日期顺延到今天起,重新填空闲、求解、发布新版本。

## 出错时

脚本遇到下列情况会停下并用中文说明原因,不会继续:

- 管理员用户名 / 密码错误,或账号不是管理员;
- 演示演出里混进了非演示成员(先在网页上移除);
- 「审核员」还参加了别的演出(先移出,否则审核员会看到真实数据);
- 用户名 `appreview` 已被别的账号占用(加 `--username` 换一个);
- 求解没有得到可发布的排练表(会附上诊断摘要)。

## 注意

- 管理员的演出列表里会多出这场演示演出;成员端看不到(他们不在这场演出里)。
- 审核通过后:在演示演出的「人员」里点「审核员」→ 停用账号即可。演示演出和成员建议留着:以后每次提交新版本都要再审,重跑脚本会重新启用账号、顺延日期、换新密码。
- `SEASON_ADMIN_USER` / `SEASON_ADMIN_PASSWORD` 环境变量可以代替交互输入,只在本机测试时用,不要写进 shell 历史或脚本。
